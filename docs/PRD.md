## 1. 背景与问题

淘宝等多账号运营需要在同一台 Windows 电脑上同时维护多个账号。平台会综合浏览器指纹、出口 IP、登录态、操作行为等信号判断账号关联。传统做法是用多个 Chrome 快捷方式或第三方指纹浏览器，存在以下问题：

1. 多个环境共用本机 IP 或相同指纹，容易被平台关联。
2. 依赖外部指纹浏览器，成本高、可控性差，内核版本和接口受制于第三方。
3. 环境、代理、Cookie、账号备注分散在 Excel 和多个工具里，难以批量管理。
4. 团队成员共用一套环境时缺少权限边界，容易误操作或泄露登录态。

本项目要做一个**本地运行、自己内置浏览器内核、自己管理指纹与代理**的多账号环境管理器。

## 2. 产品定位

**一款 Windows 本地多账号浏览器环境管理器**：

- 自带本地 Firefox 147/150/151 多版本内核，可选本地 Chrome 内核
- 每个环境独立 profile、独立指纹、独立代理出口、独立登录态
- 不依赖 AdsPower 等外部指纹浏览器
- 通过 Web 控制台管理环境、节点、订阅、成员和备份
- 可打包成单文件 EXE，双击即用

一句话：**把“多开浏览器 + 独立指纹 + 独立代理 + 团队权限”做成一个自己可控的本地软件。**

## 4. 用户与角色

### 4.1 用户画像

- **老板/管理员**：管理所有环境、节点、成员和备份，关注账号安全和整体效率。
- **运营主管/运维**：创建环境、配置代理、批量启动，不能管理成员。
- **操作员**：只启动/停止被授权的环境，执行日常登录和运营。
- **只读成员**：查看环境状态和配置，不能修改或启动。

### 4.2 角色权限矩阵

| 动作 | 管理员 admin | 运维 manager | 操作员 operator | 只读 viewer |
|---|---:|---:|---:|---:|
| 查看环境 | ✅ | ✅ | ✅（授权范围） | ✅（授权范围） |
| 启动/停止环境 | ✅ | ✅ | ✅（授权范围） | ❌ |
| 新建/修改/删除环境 | ✅ | ✅ | ❌ | ❌ |
| 管理节点/订阅 | ✅ | ✅ | ❌ | ❌ |
| 导出 Cookie | ✅ | ✅ | ❌ | ❌ |
| 调整窗口布局 | ✅ | ✅ | ✅ | ❌ |
| 窗口同步 | ✅ | ✅ | ✅ | ❌ |
| 管理成员 | ✅ | ❌ | ❌ | ❌ |
| 云端同步 | ✅ | ✅ | ❌ | ❌ |

> 管理员不受环境范围限制；其他角色的 `envScope` 为空表示全部环境，非空表示仅授权环境。

## 5. 核心概念

| 概念 | 定义 |
|---|---|
| 环境（Environment） | 一个账号/店铺对应的独立浏览器配置单元 |
| 内核（Kernel） | 浏览器本体，当前支持本地 Firefox 147.0.4 / 150.0 / 151.0、本地 Chrome；环境按 type+version 选择 |
| Profile | 内核使用的独立用户数据目录，保存 Cookie、缓存、登录态 |
| 指纹（Fingerprint） | UA、语言、时区、屏幕、CPU、内存、Canvas、WebGL 等设备信号 |
| 节点（Node） | 一个代理服务器配置（协议、地址、端口、账号密码） |
| 代理链（Chain） | 多个节点按顺序转发，形成多级出口 |
| 订阅（Subscription） | 远程代理节点列表，可定时拉取并更新节点池 |
| 动态 IP | 每次启动环境时从提取链接获取一个新出口 |
| 环境锁 | 对环境修改/导出设置密码保护，防止误操作 |
| 回收站 | 软删除环境，可恢复；彻底删除需二次确认 |

## 6. 功能需求

### FR-01 环境管理（P0，已实现）

- 新建环境字段：编号、名称、平台、启动网址、备注、分组、标签、代理节点、浏览器内核。
- 环境编号只允许字母、数字、下划线、短横线，创建后不可修改。
- 支持编辑、克隆、批量选择、批量启动/停止、移入回收站、恢复、彻底删除。
- 环境列表显示：运行状态、内核类型、屏幕、硬件、显卡、UA、代理、出口 IP。
- 默认内核为 **Firefox 150.0 · 本地内核**，新建时不需要任何外部环境 ID。

**验收**

- 新建环境不填内核时，保存为 `browserBackend=firefox`、`kernelVersion=150.0`。
- 列表显示 `Firefox 150.0·本地` 徽标。
- 旧数据 `browserBackend=ads` 自动按 `firefox/150.0` 运行，不再调用外部服务。

### FR-02 多内核切换（P0，已实现）

- 支持两种内核类型，Firefox 按版本并存：
  - `firefox`：本地 Firefox 147.0.4 / 150.0 / 151.0
  - `local`：本地 Google Chrome
- 环境设置里可切换内核；运行中的环境必须先停止才能切换。
- 内核信息持久化在环境配置中，重启软件后保持。
- 切换内核不自动迁移登录态；需要重新登录属于预期行为。

**验收**

- 环境设置切换 `firefox` ↔ `local` 后，`kernelVersion` 分别为 `150.0` / `system`。
- 运行中切换返回 409，并提示先停止环境。

### FR-03 内核管理（P0，已实现）

- 顶部「内核」页展示已安装内核的名称、版本、路径、状态。
- 任一 Firefox 版本未安装时提供「下载并安装」：
  - 从 Mozilla 官方对应版本的 `win64/en-US` 下载
  - 读取官方 `SHA256SUMS` 校验
  - 调用本机 7-Zip 解压到 `kernels/firefox/<version>/extract/core`
  - 显示下载/校验/解压进度
- 已安装时不重复下载，只显示版本与路径。
- 不允许用户传入任意下载 URL，避免 SSRF。

**验收**

- 空目录下点击下载，最终 `firefox.exe` 版本与选择一致（147.0.4 / 150.0 / 151.0）。
- SHA256 不匹配时任务失败并显示原因。
- 已安装时点击下载返回「已安装，无需下载」。

### FR-04 Firefox 多版本隔离（P0，已实现基础版）

- 每个环境独立 profile：`profiles/fx<version>-<环境编号>`。
- 启动前生成 `user.js`，写入：
  - 对应 Firefox 版本的 UA
  - 语言与 `navigator.languages`
  - CPU 核心数、DPR
  - HTTP/HTTPS 代理
  - 禁用 WebRTC
- 控制协议：WebDriver BiDi `ws://127.0.0.1:<端口>/session`。
- 当前版本不修改 Firefox 源码，Canvas/WebGL/时区等深层指纹仍弱于商业指纹浏览器。

**验收**

- 启动后 `navigator.userAgent` 包含所选版本的 `Firefox/<version>`。
- 代理配置写入 profile 的 `user.js`。
- 停止后进程退出，端口释放。

### FR-05 Chrome 隔离（P0，已实现）

- 每个环境独立 `--user-data-dir`。
- 通过 CDP 在 `document_start` 注入指纹覆盖脚本。
- 支持屏幕、硬件、显卡、Canvas、WebGL、Audio、语言、UA 等字段。
- 代理通过本地 sing-box 端口接入。

### FR-06 代理与节点（P0，已实现）

- 节点池支持 HTTP、HTTPS、SOCKS5 等协议。
- 支持单节点、代理链、订阅批量导入、动态 IP 提取器。
- 环境未配置代理且未开启「允许直连」时，拒绝启动，避免共用真实 IP。
- 支持代理测速、出口 IP 查询、链路测试。

### FR-07 启停与批量操作（P0，已实现）

- 单环境启动/停止。
- 全部启动/停止。
- 批量选择后启动/停止。
- 启动失败时回收已创建的代理进程，避免资源泄漏。
- 停止环境时同时停止对应 sing-box 代理。

### FR-08 窗口布局与同步（P1，部分实现）

- 窗口布局：网格、横向平铺、纵向平铺、层叠。
- 窗口同步：主窗口操作同步到从窗口。
- **限制**：窗口同步与布局依赖 CDP，仅支持本地 Chrome；Firefox 多版本使用 BiDi，当前会明确拒绝。

### FR-09 Cookie 导入导出（P0，已实现）

- 支持 JSON、Netscape 格式导入/导出。
- 本地 Chrome：环境停止时直接读写 profile Cookie 数据库。
- Firefox 多版本：环境运行时通过 BiDi `storage.getCookies / storage.setCookie`。
- 支持按域名过滤、批量导出。

### FR-10 导入导出与备份（P1，已实现）

- Excel/CSV 批量导入环境。
- 下载 Excel 模板。
- 配置导出：完整版（含凭据）/ 脱敏版。
- WebDAV 云端备份与恢复。
- 导入时已存在的环境默认跳过，不覆盖设备身份。

### FR-11 成员与登录（P0，已实现）

- 首次使用：登录页「注册新用户」，第一个账号自动成为管理员。
- 已有成员：自助注册为「待授权只读」，管理员分配环境范围后才可见数据。
- 管理员可在「成员」页添加、编辑、停用、删除成员。
- 管理员忘记密码：本机登录页「忘记管理员密码？」可重置，无需旧密码。
- 密码只保存加盐哈希，不提供查看原密码功能。

**验收**

- 空成员库注册第一个账号 → 角色 `admin`。
- 已有管理员时注册 → 角色 `viewer`、`pending=true`、看不到环境。
- 本机重置管理员密码后旧会话失效，新密码可登录。

### FR-12 环境锁与回收站（P0，已实现）

- 环境可设置修改/导出密码。
- 上锁环境在修改、删除、导出 Cookie 时校验密码。
- 删除环境先进入回收站，可恢复；彻底删除需二次确认。

### FR-13 日志与诊断（P1，部分实现）

- 启动/停止/代理/成员操作写入运行日志。
- 内核下载任务显示状态、进度、错误。
- 日志不得输出密码、Token、Cookie 明文。

### FR-14 环境独立下载目录（P1，待开发）

- 每个环境固定 `profiles/<env>/downloads`。
- Chrome 通过 CDP `Browser.setDownloadBehavior` 指定下载路径。
- Firefox 通过 `browser.download.dir`、`browser.download.folderList=2` 指定。
- 环境列表提供「打开下载目录」。

### FR-15 Firefox 深层指纹扩展（P1，待开发）

- 通过 WebExtension 在 `document_start` 注入：
  - 时区覆盖（`Intl.DateTimeFormat`、`Date.getTimezoneOffset`）
  - Canvas/WebGL 噪声
  - 屏幕尺寸、硬件并发、设备内存
- 目标：让本地 Firefox 多版本的指纹强度接近商业指纹浏览器。

### FR-16 多版本内核注册表（P0，已实现）

- 支持 Firefox 147.0.4 / 150.0 / 151.0 并存，后续可扩展到 ESR。
- 环境保存 `type + version`，启动时按版本解析内核路径。
- 内核包元数据包含版本、SHA256、安装路径、可用状态。
- 目录结构对齐 AdsPower：`kernels/firefox/<version>/extract/core`。

## 7. 关键流程

### 7.1 首次启动

1. 双击 `多账号环境管理器.exe`。
2. 浏览器自动打开 `http://127.0.0.1:8787`。
3. 如果成员库为空：登录页点「注册新用户」，第一个账号成为管理员。
4. 如果已有成员：输入账号密码，或点「忘记管理员密码？」重置。

### 7.2 创建环境

1. 环境管理 → 「+ 新建环境」。
2. 填写编号、名称、平台、启动网址。
3. 浏览器内核保持默认「Firefox 150.0 · 本地内核」，也可切换 147.0.4 / 151.0。
4. 选择代理节点（强烈建议每个环境不同出口）。
5. 保存 → 列表出现新环境。

### 7.3 切换内核

1. 停止环境。
2. 点「分组/设置」。
3. 浏览器内核选择 Firefox 版本（147.0.4 / 150.0 / 151.0）或本地 Chrome。
4. 保存，重新启动。

### 7.4 下载 Firefox 内核版本

1. 顶部「内核」页。
2. 选择 147.0.4 / 150.0 / 151.0 中未安装的版本 → 点「下载并安装」。
3. 等待下载、校验、解压完成。
4. 状态变为「已安装」。

### 7.5 忘记管理员密码

1. 登录页点「忘记管理员密码？」。
2. 输入管理员用户名（如 `admin`）。
3. 设置新密码（≥6 位），确认。
4. 点「重置并登录」；旧会话全部失效。

## 9. 非功能需求

### 9.1 兼容性

- Windows 10/11 x64。
- 源码运行：Python 3.10+。
- EXE 运行：无需安装 Python。
- 浏览器内核：本地 Firefox 147.0.4 / 150.0 / 151.0、本地 Chrome。

### 9.2 性能

- 100 个环境列表加载 < 1 秒（不含指纹详情渲染）。
- 单环境启动 < 10 秒（内核已就绪、代理正常）。
- 内核下载显示进度，87 MB 包在正常网络下 1 分钟内完成。

### 9.3 可靠性

- 配置文件原子写入，断电不产生半截 JSON。
- 启动失败自动回收代理进程。
- 内核下载使用 `.part` 临时文件和 SHA256 校验。
- 环境状态文件与进程 PID/端口绑定，避免误关其他实例。

### 9.4 安全与隐私

- 默认仅监听 `127.0.0.1`。
- Host/Origin 本机校验，防止 DNS rebinding 和恶意网页打本地接口。
- 密码使用 PBKDF2 加盐哈希（200,000 轮）存储。
- 日志不输出密码、Token、Cookie 明文。
- 内核下载地址固定，校验官方 SHA256。

### 9.5 可维护性

- 模块边界清晰：存储、指纹、浏览器、代理、成员、同步、内核管理。
- 所有持久化数据集中在 `data/`，删除/迁移不影响程序本体。
- 内核包与 EXE 分离，升级内核不需要重新打包 EXE。

## 12. 风险与开放问题

| 风险 | 影响 | 应对 |
|---|---|---|
| 本地 Firefox 深层指纹弱于商业内核 | 平台关联概率较高 | 下一版加 WebExtension 注入；强场景仍可用 Chrome CDP |
| Firefox 时区仍是系统时区 | 代理国家与浏览器时区不一致 | 扩展注入时区覆盖 |
| 内核下载依赖 7-Zip | 无 7z 时无法解压 | 明确报错；后续内置解压库或自带 7z |
| EXE 单文件 + 外部内核 | 拷贝 EXE 忘记带 `kernels` 会启动失败 | 启动时检测并提示；内核页显示路径 |
| 本机管理员密码重置无旧密码 | 本机其他用户可重置 | 仅监听 127.0.0.1；后续可加恢复码 |
| 平台风控 | 任何指纹方案都不能保证不关联 | 产品定位为环境管理，不做绕过承诺 |
